# Соответствие разделов ПДД: новый курс → действующая автошкола

Статус: **предварительная схема на проверку при импорте**. Не использовать для автоматической замены прогресса или продовых данных.

Источник: `motostrelok1/edu.dvizh-teory/public/sections.json` (30 разделов). Цель: `src/pages/pddTopics.ts` (38 тем). Машиночитаемая карта: [pdd-course-topic-map.json](../tools/pdd-course-topic-map.json).

## Правила

- Основные правила `s1…s26` соответствуют числовым темам `1…26` соответственно; значения сверяются с исходным JSON до импорта.
- Объединённая глава `signs` соответствует **8 темам 27–34** (по категориям знаков). Внутри главы требуется сохранение якорей/кодов знаков; **нельзя** считать просмотр всей главы эквивалентом просмотра всех восьми прежних тем.
- Объединённая глава `markup` соответствует **35 и 36**; требуется отделить горизонтальную и вертикальную разметку при переносе отметок.
- `dopusk` → **37**, приложение с неисправностями → **38**. Значение ID последнего приложения в карте `faults` является **предположением**, которое должен подтвердить скрипт preflight по реальному источнику; если там другой ID, исправить карту до продолжения.
- Текущие URL `/student/theory/course/pdd/:topicId` содержат **старые числовые ID**, их нельзя молча переназначать новому содержимому. Добавить alias/redirect после реализации новых страниц.
- Историю чтения `read-pdd-topics` нельзя перезаписывать или распределять на несколько новых страниц автоматически. Нужна явная политика миграции прогресса и сохранение исходных отметок.
- Видео и аттестация автошколы не входят в эту карту.

## Проверка

```bash
python3 tools/pdd_course_preflight.py /path/to/edu.dvizh-teory/public/sections.json
python3 tools/check_pdd_topic_map.py /path/to/edu.dvizh-teory/public/sections.json
```

Второй скрипт проверяет все ожидаемые source ID, отсутствие лишних/повторяющихся сопоставлений, покрытие 38 старых тем и выводит ошибки. Оба инструмента работают **только на чтение**, ничего не пишут в Supabase.
