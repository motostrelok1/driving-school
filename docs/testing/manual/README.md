# Ручные тест-кейсы — как отмечать

**Проект:** dvizh-school.ru. **Дата подготовки:** 27.10.2026. **Issue:** #210. **Статус:** готово для ручного выполнения, **не означает**, что все кейсы пройдены.

1. Перед прогоном вписать дату, окружение, версию приложения, роль и тестовый аккаунт без пароля.
2. В каждом сценарии поставить [x] только после прохождения; при проблеме оставить [ ] и вписать «FAIL» с ссылкой на issue. Если функция временно отключена — «BLOCKED», не ставить PASS.
3. После любого отклонения фиксировать фактический результат, URL/маршрут, время, скриншот без PII.
4. Изменяющие данные кейсы выполнять в тестовом окружении или только на специально созданных тестовых аккаунтах. Безопасные read-only проверки допускаются на production.
5. Текущие границы P0: Cloud → VDS перенесены пользователи и «Теория»; вождение disabled; старые чаты/расписание/оплаты/документы не переносились. Тесты этих функций не должны ожидать старых данных.

**Данные прогона:** дата: ____ · среда: ____ · браузер/устройство: ____ · релиз/коммит: ____ · исполнитель: ____.
