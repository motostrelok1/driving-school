# Спецификация: Tiptap в редакторе уроков теории ПДД

Статус: **запланировано, без внедрения**. Область: администратор /admin/pdd/preview, компонент `src/components/PddDraftEditor.tsx`, читатель `src/pages/StudentPublishedPddPage.tsx`. Отдельная задача от замены тренировочных вопросов официальными билетами.

## Цель
Встроить свободное ядро Tiptap (с совместимыми по лицензии расширениями, без платных облачных функций) для оформления учебного текста визуально, без HTML-редактирования. Не повреждать существующие опубликованные разделы курса, изображения и quiz-блоки.

## Текущее устройство
- Черновик состоит из массива блоков с полем `type` и полями `text/title/term/def/intro/src/...`. Редактор PddDraftEditor сейчас использует textarea и редактор изображений.
- Административная страница держит черновики в `pdd_course_drafts`, версии в `pdd_course_draft_revisions`, публикации в `pdd_course_published_revisions`. Публикация отделена от сохранения.
- Читатель курсанта `StudentPublishedPddPage.tsx` отображает известные типы блоков. Quiz остаётся отдельной структурой; текущие 32 раздела и импортированные материалы должны быть совместимы.

## UX редактора
1. В существующем списке блоков при выборе текстового блока открывается WYSIWYG-поле Tiptap, сохраняющее все возможности списка (добавить, переставить, удалить блок).
2. Русская панель, закреплённая над полем: Обычный текст; H2/H3; жирный; курсив; подчёркивание; зачёркивание; маркированный/нумерованный список; цитата; ссылка; отмена/повтор; очистить оформление. Дополнительно: таблицы, выделение маркером, выравнивание — отдельным этапом.
3. Специализированные шаблоны *Правило*, *Определение*, *Внимание*, *Пример*, *Ошибка водителя*, *Запомнить* — семантические блоки, оформление одинаково в редакторе, предпросмотре и кабинете курсанта.
4. Заголовки страницы и общая иерархия курса остаются управляемыми редактором раздела. Не разрешать произвольный HTML/CSS/JS или свободные цвета без палитры.
5. Вставка текста из Word/Google Docs — очищать небезопасную разметку, нормализовать списки и ссылки. Вставка изображения через существующий Storage-flow, подпись, alt-текст, ограничение размера. Мобильный предпросмотр.
6. Статус «Есть несохранённые изменения»; сохранение через существующую кнопку Supabase, публикация только отдельной кнопкой, история и восстановление версий не теряются. При переключении блоков предупреждать о несохранённых правках.

## Формат хранения и совместимость
- **Не заменять массив блоков Tiptap-документом целиком.** Для новых rich-text-блоков использовать отдельный тип `rich_text` с версионированным Tiptap/ProseMirror JSON `content` внутри блока. Схему полей уточнить после аудита проверки данных в SQL RPC.
- Старые блоки `p/lead/motivation/quote/topic/h2/term/example/link/img/quiz` отображать как прежде. Для них предусмотреть явную безопасную миграцию отдельного блока в rich-text, а не автоматическую массовую перезапись 32 опубликованных разделов.
- Для существующих блоков `text`/специализированных полей на этапе MVP возможен адаптер в редакторе, сохраняющий старую строку только при поддерживаемом наборе форматирования. Как только появляются marks/lists — сохранять как отдельный `rich_text`, с подтверждением преобразования и без потери соседних свойств.
- Изображения и вопросы `quiz` оставлять отдельными блоками; **не трогать** официальный банк вопросов, результаты экзаменов, нотификации и ученический прогресс.
- Поддержка опубликованных версий: сохранить прежние JSON-снимки; предусмотреть откат на предыдущую публикацию. Перед выбором формата проверить SQL-валидацию и максимальный размер payload.

## Безопасность и производительность
- Хранить JSON, не произвольный HTML. Выводить только через allowlist расширений/нод; запретить скрипты, опасные URL-схемы, обработчики событий, произвольные стили/iframe.
- Права записи — только администратор по существующим RLS/RPC. Предпросмотр и версия ученика берутся из разрешённой опубликованной ревизии.
- Ленивая загрузка редактора только на админ-странице, не загружать Tiptap в ученический bundle ради простого рендера, если можно использовать отдельный безопасный рендерер.
- Ограничение размера документа/медиа, обработка ошибок и повторной загрузки на смартфонах, контроль ререндеров при вводе, поддержка клавиатуры и доступности.

## План внедрения PR
**PR-A (аудит/контракты):** инвентаризация формата, схем SQL, истории ревизий; итоговые TypeScript-типы и правила совместимости; тесты сохранения 32 старых разделов.
**PR-B (MVP редактора):** Tiptap в одном текстовом блоке, панель, списки, ссылки, история ввода, синхронизация с `onChange`, сохранение черновика в существующий Supabase.
**PR-C (рендер):** одинаковый безопасный рендер `rich_text` у администратора и курсанта, проверка на смартфонах, без изменения quiz/images.
**PR-D (учебные блоки):** шаблоны правил/терминов/предупреждений, таблицы, стили и работа с медиа; UX-финализация.

## Приёмочные критерии
- Можно создать текст с H2/H3, жирным, списком и ссылкой, сохранить черновик, перезагрузить страницу и восстановить форматирование.
- Превью и опубликованный урок в кабинете курсанта визуально совпадают; мобильная вёрстка читаема.
- Старые опубликованные 32 раздела открываются без изменений, контент/вопросы/картинки не пропадают.
- Сохранение/публикация/история/откат работают; неотредактированные блоки и полные JSON-снимки неизменны.
- Проверены XSS и недопустимые ссылки, длинные тексты, паста из Word, потеря сети.
- CI: lint, TypeScript, build, тесты парсера/рендера. Публикация только после тестирования черновика.

**Пока не делать**: внедрять редактор, менять SQL или массово конвертировать действующие уроки.
