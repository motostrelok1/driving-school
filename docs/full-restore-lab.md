# Полное тестовое восстановление Supabase — единый сценарий

Статус: **подготовлено в PR #184, НЕ проверено запуском на VDS**. Нет GitHub Actions и нет sudoers-доступа для этого скрипта.

## Что делает
- Создаёт только новые ресурсы `cloud-full-restore-rehearsal-v1` и `cloud-full-restore-rehearsal-data-v1`.
- Использует точный образ `supabase/postgres:17.6.1.136` со штатной инициализацией через `POSTGRES_USER=supabase_admin` и `migrate.sh`.
- Запускается с `--network none`, без опубликованных портов; архив подключён read-only.
- Выжидает завершения bootstrap, затем пробует в зависимостном порядке восстановить public pre-data, auth data, public data, public post-data.
- Каждая фаза `pg_restore` выполняется с `--exit-on-error --single-transaction`: любая ошибка прекращает процесс. Том и контейнер сохраняются для анализа без автоматического удаления.
- Выводит только счётчики Auth и профилей, таблиц и политик.

## Перед запуском
1. Независимый review YAML/скрипта, объёма свободных ресурсов, локально доступного образа и целостности архива.
2. Проверить, что штатная инициализация способна завершиться без доступа в Интернет: расширения pg_cron/pg_net могут требоваться при миграциях, хотя Docker network=none блокирует исходящие подключения. Не добавлять сеть ради «исправления» ошибок.
3. Принять, что одноимённый тестовый контейнер/том больше никогда не переписывается этим скриптом. Не удалять production volumes и не выдавать CI права docker.
4. Первый запуск — контролируемый root-оператор на VDS после подтверждения; не включать автоматическое выполнение.
5. После успешного запуска нужны проверки функций, владельцев, RLS, негативных проверок прав, Auth login и Storage — одних счётчиков недостаточно.

## Известные причины возможного отказа
- Облачный dump использует другой набор системных extensions/схем; часть функций зависит от storage/vault.
- В архиве `--no-owner --no-acl`, поэтому права и владельцы не восстановятся автоматически.
- `auth` bootstrap может уже содержать системные строки, конфликтующие с data-only снимком.
- Импорт public post-data может зависеть от расширений/объектов, не входящих в выбранные разделы архива.
- Инициализация Docker может требовать конфигурацию, которая отсутствует в изолированном кластере.
- Архив является устаревающим снимком. Для production нужен новый согласованный backup PostgreSQL + Storage.

## Граница безопасности
Никакие существующие БД/контейнеры/тома не изменяются, root-скрипт не принимает параметров, секреты не публикуются. Однако создание контейнера с SQL из дампа само по себе чувствительная операция; необходимо выполнить review перед её запуском. PR #169 отдельно и не должен применяться до полного теста.
