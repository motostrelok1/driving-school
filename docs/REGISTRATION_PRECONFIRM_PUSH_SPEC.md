# REG-PUSH-01: Push до подтверждения email

Статус: запланировано, не реализовано. После тестирования PWA; до релиза Driving School Kit.

Цель: после регистрации при обязательном подтверждении email предложить Web Push и отправлять только нейтральное напоминание подтвердить почту. Обычные уведомления и доступ в приложение — только после подтверждения.

## Требования
- Supabase GoTrue без email auto-confirm может не выдавать пользовательскую сессию; обычные authenticated вызовы до подтверждения не использовать.
- Запрашивать разрешение на push только по кнопке пользователя; отсутствие поддержки, отказ или закрытие страницы не должны блокировать регистрацию.
- Серверная привязка браузерной подписки к регистрации должна быть подтверждена. Не доверять присланным браузером user_id/email/OneSignal ID как доказательству владения. Рассмотреть краткоживущий одноразовый enrollment-токен, хешированное хранение, rate limit и очистку.
- Если безопасную привязку доказать нельзя, не отправлять push до подтверждения.
- Только два допустимых события: одно нейтральное сообщение после согласия и не более одного напоминания через 24 часа при неподтверждённом email. Ни ФИО, ни расписания, ни документов, ни содержания чатов, ни финансовых сведений.
- Подтверждение, отписка, удаление/истечение регистрации отменяют напоминания. После входа переход к обычной авторизованной подписке.
- Test: Mailpit и mock OneSignal; реальные push и письма наружу отключены. Production включать отдельным feature flag после приёмки.

## Этапы реализации
1. Уточнить схему signup/email-confirmation и исследовать безопасный enrollment flow без сессии.
2. Спроектировать SQL/RLS, TTL, антиспам, серверный токен и Edge Function с фиксированными текстами.
3. Экран ожидания письма: повторная отправка, кнопка согласия на уведомления, корректная обработка отказа.
4. Планировщик напоминания через 24 часа, дедупликация, очистка подписок.
5. Внести отдельную конфигурацию в Driving School Kit; универсальный Lite Core не должен содержать бизнес-логику.
6. Интеграционные тесты Mailpit+OneSignal mock и проверка реального устройства только после разрешения.

## Приёмка
- Неподтверждённый email не даёт доступа к защищённым API.
- Невозможно привязать чужую регистрацию или подписку; одноразовые токены нельзя повторить, просроченные отклоняются.
- Не более двух разрешённых нейтральных push до подтверждения; после подтверждения или отмены подписки — ни одного.
- Проверены повторный signup, несколько вкладок, отказ в разрешении, неподдерживаемый браузер, rate limiting, пересоздание аккаунта.
- SMTP на новой чистой установке реально отправляет подтверждение; при тестах используется Mailpit и не уходят настоящие сообщения.
