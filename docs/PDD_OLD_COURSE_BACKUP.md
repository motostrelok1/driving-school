# Резервная копия старого курса ПДД — PR #136

Перед переключением учеников на новый курс необходимо сохранить старые статьи из `public.pdd_articles`. PR #136 **не удаляет их и не меняет страницы учеников**.

## Порядок

1. После merge PR #136 открыть в Supabase Dashboard → SQL Editor файл `supabase/migrations/0050_backup_legacy_pdd_articles.sql`; проверить SQL и выполнить его **один раз** от имени владельца проекта.
2. Скрипт создаёт `pdd_backup.pdd_articles_before_cutover_20261014` и в одной транзакции сравнивает количество строк и контрольный хеш всех столбцов с действующей таблицей. При ошибке весь SQL откатывается.
3. Отдельно выполнить:
```sql
SELECT count(*) AS legacy_count FROM public.pdd_articles;
SELECT count(*) AS backup_count FROM pdd_backup.pdd_articles_before_cutover_20261014;
```
Числа должны совпадать и быть больше нуля. **Не следует ожидать ровно 38 строк**: 38 пунктов в каталоге не гарантируют, что все статьи заполнены в таблице. Кроме того, список прежних 38 тем находится в исходном коде `src/pages/pddTopics.ts`, а не только в `pdd_articles`. Этот код остаётся в Git.

## Ограничения

- Эта копия охватывает только таблицу `pdd_articles`, не видеоматериалы, билеты, профили и весь проект Supabase. Перед реальным переключением желательно также выполнить штатный полный бэкап БД.
- Снимок не обновляется автоматически после изменений старых статей. **Не запускайте миграцию повторно** — одноимённая таблица уже будет существовать.
- Восстановление нужно проектировать и тестировать отдельно; не исполнять произвольное `DELETE` или `TRUNCATE` в действующей таблице.
- Таблица хранится в отдельной схеме без разрешений клиентским ролям; SQL Editor владелец проекта сможет её читать.
- Сначала будет создан отдельный ученический просмотр 32 опубликованных тем, затем админское управляемое переключение и откат. До этого старые 38 тем продолжают работать.
