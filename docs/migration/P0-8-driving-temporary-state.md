# P0.8 — Временное состояние раздела «Вождение» после миграции на собственный Supabase

## Контекст

Миграция PR #208 переносит только пользователей и раздел «Теория».
Данные разделов «Сообщения» и «Вождение» не переносятся: таблицы
`driving_course_categories`, `instructor_students`, `lessons`, `messages` и
связанные пусты (кроме keeper-остатков). Этот документ фиксирует согласованное
временное поведение раздела «Вождение» и порядок его включения.

## Временное состояние (заглушка)

Доступ к разделу «Вождение» управляется флагом `profiles.driving_enabled`:

- После импорта `driving_enabled = false` у всех 30 перенесённых пользователей
  и keeper-аккаунтов.
- `StudentPracticePage` при `driving_enabled = false` показывает карточку
  «Вождение недоступно — доступ к разделу ещё не открыт администратором»
  (`src/pages/StudentPracticePage.tsx`, проверка `drivingDisabled`).
- Пустые списки инструкторов/слотов покрываются существующими состояниями
  («Зарегистрированных инструкторов пока нет», «Записей пока нет»).

Таким образом отдельный код заглушки не требуется — флаг `driving_enabled`
уже является корректной и понятной заглушкой с текстом для пользователя.

## Порядок включения «Вождения» (после переключения production)

Выполняется администратором после того, как данные раздела будут перенесены
или созданы заново:

1. Создать категории курсов вождения
   (раздел «Вождение» в настройках администратора, RPC `save_driving_course_category`).
2. Привязать учеников к инструкторам
   (RPC `reassign_student_instructor` / экран пользователей администратора).
3. Включить ученикам флаг `driving_enabled` (экран пользователя администратора).
4. Проверить запись: создание слота инструктором → запись учеником
   (RPC `create_my_driving_slot` / календарь инструктора).

## Что осталось за пределами этого этапа

- Перенос истории занятий, расписания, оплат, документов и сообщений —
  отдельная фаза миграции (за пределами P0/P0.8).
- Keeper-остатки (4 группы, 2 слота вождения) не удаляются до отдельного
  решения.
