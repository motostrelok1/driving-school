# Официальное тестирование: назначение и прохождение

Администратор: **Пользователи → карточка ученика → Тестирование**. Можно назначить зачёт или внутренний экзамен, увидеть назначения/результаты и отменить назначение до начала попытки. Пересдача — новое назначение, предыдущая попытка сохраняется.

Зачёт: выбранные темы ПДД, 1–800 вопросов, 1–180 минут, допустимые ошибки меньше количества вопросов, открытие и дедлайн. Внутренний экзамен: фиксированный шаблон автошколы — 20 случайных проверенных вопросов, 20 минут, не более 2 ошибок. Дополнительных вопросов нет; соответствие процедуре государственного экзамена не заявляется. Сроки вводятся и отображаются по Москве.

Ученик: **Теория → Тестирование** (`/student/theory/testing`). Блоки «Доступно сейчас», «Назначено», «История попыток». «Начать» создаёт серверную попытку, «Продолжить» восстанавливает её. Ответ сохраняется сразу после выбора и не меняется. Закрытие браузера не останавливает время. Итог считает сервер; вопросы без ответа считаются ошибками, истечение времени означает «Не сдано».

## Установка после merge этапа 2

Миграция `0034_theory_assessments.sql` из PR #93 должна быть уже применена. Если этап 1 установлен, повторно её не запускать.

1. На сервере получить код и вывести новую миграцию:

   ```bash
   cd /var/www/driving-school && git pull --ff-only origin main
   cat supabase/migrations/0035_theory_assessment_execution.sql
   ```

2. Скопировать весь SQL из вывода `cat`. Открыть **Supabase → проект `dznjopipisdfrojlpxrz` → SQL Editor → New query**, вставить SQL и нажать **Run**. Применять один раз; миграция выполняется в транзакции.

3. На сервере вывести код новой Edge Function:

   ```bash
   cd /var/www/driving-school
   cat supabase/functions/send-theory-assignment/index.ts
   ```

4. Скопировать весь код из вывода `cat`. Открыть **Supabase → Edge Functions → Deploy a new function → Via Editor**, создать функцию с именем **`send-theory-assignment`**, вставить код в **`index.ts`** и нажать **Deploy**. Для существующей функции: **send-theory-assignment → Code → index.ts → Deploy**. Используются те же проектные `ONESIGNAL_APP_ID` и `ONESIGNAL_REST_API_KEY`, что у работающих push-функций; новые секреты не нужны. Cron для этой функции не нужен.

5. На сервере собрать фронтенд:

   ```bash
   cd /var/www/driving-school && npm run build
   ```

6. Открыть сайт под администратором, обновить страницу **Ctrl+F5**. В меню открыть **Банк вопросов**, нажать **Импортировать исходные билеты**. Затем подготовить проверенные вопросы по инструкции ниже. Старые назначения сохранятся; запуск станет доступен при достаточном количестве проверенных вопросов.

## Подготовка банка перед первым тестом

В исходном `public/tickets/tickets.json` найдено 795 вопросов: в билете 20 отсутствуют вопросы 6–10, у 42 записей ключ ответа отсутствует либо не соответствует ни одному варианту. Есть и содержательные расхождения с исходными изображениями, в том числе в билете 1. Поэтому импорт **не одобряет** вопросы автоматически. Исправление всего тренировочного банка остаётся отдельной задачей в `PROGRESS.md`.

В **Банк вопросов** открыть нужный билет и вопрос. Сверить текст, все варианты и правильный ответ с актуальным учебным материалом; исправить поля, при необходимости добавить/удалить вариант, выбрать правильный ответ. Для зачёта отметить подходящие темы. Нажать **Сохранить и одобрить**. Только одобренные вопросы участвуют в новых официальных попытках. Без тем вопрос доступен для внутреннего экзамена.

Для короткой проверки достаточно **одного** проверенного вопроса с выбранной темой и зачёта на 1 вопрос по этой теме. Для внутреннего экзамена нужны **не менее 20** проверенных вопросов. Для зачёта банк должен содержать не меньше назначенного количества вопросов, относящихся хотя бы к одной из выбранных тем; равномерное покрытие каждой темы не гарантируется. При нехватке вопросов кнопка «Начать» отключена, RPC также запрещает создание попытки.

**Сохранить черновик** исключает вопрос из новых попыток. Повторный импорт не перезаписывает существующие записи, исправления и одобрения. Изменение банка после старта не меняет текст, варианты и ключ ответа уже созданной попытки. Существующая тренировка по исходному JSON остаётся отдельным режимом.

## Схема, время и доступ

- `theory_assessments`: параметры назначения, автор, ученик, сроки, отмена и отметки отправки уведомления.
- `theory_question_bank`: отдельный серверный банк; чтение и редактирование только администратором через защищённые RPC. Импорт создаёт черновики, одобрение подтверждает ключ и темы.
- `theory_assessment_attempts`: одна попытка на назначение, снимок текста/вариантов и правил, серверное начало/лимит/итог. `answer_key` — закрытая колонка, недоступная клиентскому `SELECT`, включая администратора.
- `theory_attempt_answers`: уникальная пара `(attempt_id, question_index)`. Ученик получает только сохранённый выбор, без `is_correct`; правильность вычисляется по закрытому ключу.

Клиенты не могут напрямую создавать, менять или удалять назначения, банк, попытки и ответы. Ученик читает только свои данные; инструктор и аноним не имеют доступа. Все RPC проверяют роль и владельца. Приватные функции нельзя вызывать из браузера. Администратор читает результаты и назначает/отменяет тестирование, но также не записывает результат напрямую.

Старт блокирует назначение `FOR UPDATE`, как отмена; повтор запроса возвращает ту же попытку. Срок попытки — минимум из серверного начала плюс лимит и дедлайна назначения. Таймер интерфейса использует серверный timestamp и `performance.now()`; решение о приёме ответа принимает БД. Истёкшая попытка завершается при следующем запросе списка, чтении попытки, ответе или завершении. Закрытая попытка и результат не перезаписываются повторным запросом. Фронтенд хранит ссылку на попытку в URL, состояние восстанавливается из Supabase.

Удаление ученика удаляет связанные данные тестирования вместе с профилем; удаление автора оставляет назначение с `created_by = null`.

## Уведомление ученику

После назначения вызывается `send-theory-assignment` с UUID назначения. Функция проверяет администратора, получает тип/сроки из БД, сохраняет обычное уведомление в общей истории и отправляет push со ссылкой на раздел тестирования. Ошибка отправки не отменяет назначение. Для активного назначения без попытки и без подтверждённой отправки в карточке есть **Уведомить ученика**.

Служебный RPC выдаёт короткую блокировку отправки; история использует один UUID назначения и `upsert` с сохранением существующей записи. В OneSignal передаётся тот же UUID как `idempotency_key` ([документация провайдера](https://documentation.onesignal.com/reference/idempotent-notification-requests)). Статус `sent` означает принятие push провайдером; это не доказательство доставки устройству. При сбое история остаётся, блокировка снимается, отправку можно повторить.

## Что проверить на сайте

1. Под администратором одобрить 1 вопрос с темой, назначить ученику зачёт на 1 вопрос по этой теме, 2 минуты, 0 ошибок, открытие сейчас и дедлайн позже. Проверить уведомление ученика и запись в истории.
2. Под учеником открыть **Теория → Тестирование → Начать**. Сразу обновить страницу, затем закрыть/снова открыть раздел: должна быть одна попытка, прежний набор вопросов и продолжение времени.
3. Выбрать правильный ответ: «Сдано», 1 верный, 0 ошибок. Обновить страницу и открыть результат из истории. Под администратором открыть карточку этого ученика: результат виден в окне тестирования.
4. Назначить новый зачёт на 2 вопроса при наличии 2 одобренных вопросов. Ответить на один, обновить страницу: выбор сохранён и его нельзя изменить. Завершить с одним пропуском: пропуск считается ошибкой. Старый результат остаётся в истории.
5. В новом назначении дождаться окончания времени или закрыть страницу до его истечения и вернуться позже: «Не сдано», время истекло, новые ответы не принимаются.
6. Проверить будущую дату открытия и недостаточный банк: «Начать» недоступно. Внутренний экзамен доступен после одобрения минимум 20 вопросов, параметры 20/20/2.

Цветные статусы иконки, расширенная история в карточке, уведомление администратору и задачи после неуспешной попытки — этап 3.

## Автоматические проверки

`npm run build`, `npm run lint`.

`supabase/tests/theory_assessments.sql` и `supabase/tests/theory_execution.sql` запускать **только в отдельной тестовой БД** после соответствующих миграций. Нужны роли `anon`, `authenticated`, `service_role`, `auth.users`, `profiles`, `auth.uid()`, `is_admin()`. Фикстуры откатываются. Покрытие: RLS/column grants, защищённые RPC, идемпотентность, отмена/старт, проверенный банк/темы, закрытый ключ, неизменяемый снимок, сохранение и повтор ответов, пересдача новым назначением, итог/пропуски/сроки, блокировка уведомлений.

Локально дополнительно проверены браузер со связанными PostgreSQL RPC (PGlite), восстановление после потери ответа сервера, мобильная ширина и импорт реальных 795 записей; Edge Function — с имитацией БД и транспорта, без реальных push.
