# PR #180 — проверка миграции 0063 и прогресса теории

Статус: **НЕ ПРИМЕНЯЛОСЬ** на VDS в рамках этой ветки. Этот документ — обязательный gate для тестовой БД до разрешения production merge/deploy.

## Риски
- В `StudentTheorySectionPage.tsx` исторический ключ `localStorage['watched-theory-videos']` **не привязан к user_id**. На общем браузерном профиле отметки прошлого пользователя могут попасть в аккаунт следующего. До выпуска надо привязать локальный прогресс к UID или отказаться от автоматического импорта неатрибутированных отметок; тестировать переключение учеников в одном браузере.
- React UI делает запрос RPC `get_admin_student_theory_progress` и новой таблицы. Если SQL 0063 отсутствует, функциональность будет недоступна; миграция должна быть применена и испытана первой.
- `SECURITY DEFINER` в RPC проверяет `is_admin`, но при добавлении будущей роли директора и «своих учеников» этот доступ должен быть ограничен соответствующими назначениями. Не вводить расширенный доступ без пересмотра.
- SQL должна быть проверена на повторное применение, роль владельца функции, существующие search_path и GRANT/REVOKE. Удаление миграции из Git не откатывает базу.

## Тестовый порядок
1. Сделать защищённый независимый backup test PostgreSQL + Storage; не допускать доступа к production.
2. Проверить на `driving-school-supabase-test` отсутствие/наличие миграции и таблицы; если отсутствует — выполнить `0063_theory_video_progress.sql` только на тестовом стеке под отдельной ролью bootstrap и зафиксировать версию. Не менять production cron.
3. Проверить `SELECT`/ `INSERT` authenticated первого ученика; второй ученик не видит и не может менять его строки; anon не видит; отрицательный тест на неизвестный video_id; `UPDATE` и `DELETE` для student запрещены.
4. Администратор видит только агрегат; второй студент не может выполнять admin RPC. Проверить подсчёт опубликованных ПДД, пяти видео и пустые значения.
5. Проверить браузером: отметить видео → перелогин → сохранено; другое устройство → синхронизировано; переключение ученика на том же устройстве → **без утечки чужого локального прогресса**; отключение сети и последующая синхронизация.
6. Realtime и Storage регрессии; `npm ci && npm run lint && npm run build` и обязательная проверка PR.
7. Деплой только после разрешения production baseline/migration ledger; резервная копия и plan rollback.

## Критерий готовности
`0063` проверена на тестовой БД, RLS и разграничение студентов проверены, локальный прогресс не перетекает между аккаунтами, UI проверен; CI зелёный; production SQL gate согласован. До этого PR **не сливать** и не выкатывать UI в production.
