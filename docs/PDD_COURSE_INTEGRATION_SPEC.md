# Интеграция учебного курса ПДД и визуального редактора

Статус: утверждено направление интеграции; поэтапная реализация. 2026-10-13.

## Цель

Заменить **только материал ПДД** внутри `/student/theory/course` материалами из `motostrelok1/edu.dvizh-teory` (30 разделов, лекции, изображения, тесты) и расширить действующий редактор `/admin/pdd` до визуальной CMS. Видеоуроки, экзамены, билеты, существующие назначения и учётные записи не менять.

## Обнаруженное в действующем проекте

- `AdminPddPage.tsx` — JSON-редактор и загрузка файла.
- `usePddArticle` и `useUpsertPddArticle` — чтение/запись таблицы `pdd_articles`.
- `0013_pdd_articles.sql` — RLS: чтение authenticated, запись admin.
- `StudentTheorySectionPage.tsx` — список по `pddTopics` (38 пунктов), `StudentPddTopicPage` читает `paragraph/image`; прогресс чтения `read-pdd-topics` в localStorage.
- В источнике `edu.dvizh-teory/public/sections.json` — 30 разделов с блоками `motivation/topic/lead/quote/term/example/quiz/p/h2/img`.
- Исходные изображения хранятся отдельно в `public/img`; в источнике есть ссылки на знаки/разметку.

## Правила интеграции

1. **Один Supabase и одна авторизация**: использовать действующую инфраструктуру `driving-school`, без регистрации второй базы/пользователей.
2. **Никакого переключения курсантов в первом PR**. До готовности нового рендера, медиапутей, контроля ссылок и отката старые страницы сохраняются.
3. **Полная замена каталога ПДД**: ровно 30 тем из источника вместо прежних 38. Использовать ID исходного курса без таблиц соответствий; не переносить прежние отметки прочтения на новые темы.
4. Разделить immutable опубликованные ревизии, черновики и метаданные медиа. Не редактировать непосредственно JSON-снапшот из Python-генераторов.
5. Нормативные цитаты защищены от случайного изменения, авторские объяснения редактируемы.
6. Материалы нового учебника не заменяют аттестацию и экзамены в основной автошколе.
7. Перед очисткой `pdd_articles` сделать экспорт/резервную копию. После подтверждённого импорта и проверки выполнить управляемую очистку старых 38 тем и публикацию новых 30, с возможностью отката из резервной копии.

## Функции редактора

- Меню разделов, поиск, создание/редактирование/архивация/перестановка страниц.
- Типизированные блоки: текст, заголовок, нормативная цитата, объяснение, термин, пример, тест, изображение, список и ссылки.
- Изображения: загрузка PNG/JPEG/WebP в Storage, выбор из медиабиблиотеки, замена, удаление из страницы, процентная ширина, max-width, выравнивание, подпись и alt. Физическое удаление файла только после проверки использования.
- Ссылки: на раздел по стабильному ID, на блок, знаки/разметку и внешние HTTPS-URL. Предупреждение о битых ссылках.
- Автосохранение черновиков, публикация только после валидации, предпросмотр для desktop/mobile, версии, откат, журнал действий.
- Запрет произвольного HTML/JS, серверная валидация типов, RLS для админа, контроль загрузки файлов и защита от перезаписи чужого черновика.

## Критерии приёмки

- [ ] Работают все исходные 30 разделов, блоки, изображения и проверочные вопросы.
- [ ] Каталог содержит ровно 30 тем источника; старые ID не используются и не сопоставляются; устаревшие ссылки обрабатываются безопасным возвратом к списку.
- [ ] Курсанты читают только опубликованную версию.
- [ ] Администратор редактирует без JSON, меняет размер и позицию картинок и ссылки.
- [ ] Публикация атомарна, можно откатиться на предыдущую ревизию.
- [ ] Нормативные выдержки отделены от авторских объяснений.
- [ ] RLS не допускает записи курсантом даже через прямой API.
- [ ] Старые отметки прочтения ПДД сбрасываются для нового каталога, остальные данные учеников и результаты аттестации остаются без изменений.
- [ ] Сборка и тесты в PR зелёные; миграции запускаются отдельно после проверки.

## Порядок запуска

Выкатить схему и импорт **без активации**, затем предпросмотр администратору, после успешных проверок переключение под флагом. Держать быстрый откат на текущий курс. Миграции Supabase — вручную через SQL Editor только после согласования.
