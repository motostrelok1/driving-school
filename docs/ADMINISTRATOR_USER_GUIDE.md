# Инструкция администратора Driving School

**Статус:** руководство по функциям текущего `main`, 17.10.2026. Перед использованием на production проверить интерфейс в своей версии PWA. Тестовая среда: https://test.dvizh-school.ru; здесь письма перехватывает Mailpit, реальные push отключены. Не используйте реальные данные для учебных проверок.

## Вход и разделы

Войдите под ролью **«Администратор»**: главная страница `/admin`. Боковое меню: **Панель управления, Расписание, Пользователи, Группы, Переписка, Задачи, ПДД, Настройки, Банк вопросов**. Если раздел или действие недоступны, проверьте права аккаунта.

## Пользователи (`/admin/users`)

**Найти ученика:** выберите «Пользователи», используйте поиск по ФИО/фильтр роли, разверните карточку. Проверьте программу, контакты, документы, часы вождения, доступную теорию и действия. Пустой показатель не всегда означает ноль — данные могут ещё не синхронизироваться.

**Создать пользователя:** действие добавления → заполните обязательные поля формы (ФИО, email, телефон и др.) → задайте роль → сохраните → найдите пользователя поиском. Не публикуйте пароли в чатах; предпочтительнее безопасное восстановление пароля.

**Изменить профиль:** карточка → редактировать → сохранить → проверить результат. Изменение роли — привилегированная операция.

**Назначить/сменить инструктора:** карточка ученика → выбор инструктора → подтвердить. После смены проверьте будущие брони и чаты: ранее запланированные занятия могут отменяться, освобождая слоты; прежний трёхсторонний чат должен закрываться, сохраняя историю. Не проверяйте это на реальном ученике без его согласия.

**Включить доступ к вождению:** карточка ученика → управление доступом → разрешить и сохранить. Если ученик видит, что доступ приостановлен, сначала проверьте этот статус, назначение инструктора и условия программы.

**Финансы:** карточка ученика содержит расчёты/корректировки. Сверяйте график и фактические платежи; не отмечайте платёж без подтверждения.

**Документы:** открывайте привязанные к ученику файлы и задачи, проверяйте статус. Студенческие документы хранятся в приватном Storage — не раздавайте прямые ссылки посторонним.

**Пароль:** действие отправки ссылки восстановления есть в пользовательском разделе. В тесте письмо находится в Mailpit, не во внешней почте.

## Группы

«Группы» → «Добавить группу» → введите название → «Создать группу». Для существующей группы — «Редактировать» → «Сохранить». Есть поиск учеников по ФИО. Перед удалением учтите: ученики могут остаться без группы. Проверьте их распределение после операции.

## Расписание (`/admin/schedule`)

**Право инструктора создавать расписание:** откройте блок «Право инструктора управлять расписанием», найдите инструктора, дайте разрешение. До выдачи права инструктор может видеть своё расписание, но не редактировать его.

**Создать слот:** «Добавить занятие по вождению» → выберите инструктора, дату, время, длительность, место встречи при необходимости → сохранить → проверить слот в сетке. Учитывайте пересечения и настройки курса.

**Записать ученика вручную:** открыть свободный слот → действие бронирования → поиск по ФИО/email → выбрать ученика → подтвердить. Проверьте, что у ученика разрешено вождение и достаточно часов.

**Перенести/удалить:** открыть слот → «Перенести» либо «Удалить» → подтвердить → проверить результат. Для занятого слота сначала оцените последствия для брони ученика.

## Переписка (`/admin/messages`)

Вкладка **«Уведомления»**: «Новое уведомление» → «Личное» или «Групповое» → выбрать получателей (поиск или готовые аудитории) → ввести содержание → «Отправить». Перед групповой рассылкой обязательно проверить круг адресатов.

Вкладка **«Переписка»**: «Новый чат» → личный/групповой → участники → «Создать чат»; существующий чат открыть из списка и отправить ответ.

Трёхсторонний чат администратор–ученик–инструктор создаёт администратор по предусмотренному процессу; ученик и инструктор отвечают. При смене инструктора прежний чат закрывается и остаётся в истории. В тесте доставка реальных push отключена — запись сообщения в БД не означает получение push.

## Задачи (`/admin/tasks`)

Просмотрите «Требуют внимания» и заявки «Включить переписку админ — ученик — инструктор». Для заявки проверьте ученика/инструктора → активируйте чат → убедитесь, что он появился в переписке. Для документов используйте переход из задачи к карточке ученика, устраните проблему и проверьте обновление статуса. Не создавайте второй чат, если активный уже есть.

**Пока задачи не разделены по закреплённым администраторам.** Логика директора, назначения ответственного, передачи незавершённых задач и открытых чатов описана в планируемом PR #200, но не является функцией текущего приложения.

## ПДД и банк вопросов

**ПДД:** откройте раздел, выберите учебный материал, отредактируйте его, сохраните и проверьте через предпросмотр. Перед публикацией убедитесь в корректности текста, изображений и заданий. Модернизация редактора — отдельная задача.

**Банк вопросов:** импорт/редактирование вопросов → проверить варианты ответов, правильный ответ и темы → одобрить вопросы. Не считайте импортированный черновик готовым к экзамену. Доступность функций зависит от применения миграции 0035.

**Назначить тестирование/экзамен:** «Пользователи» → карточка ученика → действие назначения теоретического тестирования → указать тип, количество вопросов, сроки и остальные параметры формы → подтвердить → проверить наличие задания у ученика. Ответы должны проверяться сервером; история попыток сохраняется отдельно.

## Настройки

В «Настройки» администратор управляет категориями программ вождения, краткими названиями и вариантами длительности (минуты/академические часы). После сохранения проверьте доступность новых опций при создании слота. Не удаляйте используемую категорию без проверки последствий.

## Ежедневный порядок

1. Открыть «Задачи»: новые обращения, неисполненные заявки и документы.
2. Проверить «Переписку»: ответы ученикам/инструкторам, важные уведомления.
3. Проверить «Пользователей»: регистрации, доступ к вождению, документы, инструкторы.
4. Открыть «Расписание»: свободные слоты, записи, конфликты и изменения.
5. В конце дня проверить остаток задач и важные записи в истории.

## Если что-то не работает

| Симптом | Проверка |
|---|---|
| Ученик не может бронировать | Доступ к вождению, инструктор, остаток часов, наличие свободных слотов |
| Инструктор не создаёт слоты | Его разрешение управлять расписанием |
| Нет уведомления push | История и статус доставки; в тесте OneSignal mock |
| Не пришло письмо | SMTP, email confirmation и Mailpit для теста |
| Нет доступа к чату | Участники, смена инструктора, закрытие чата |
| Экзамен недоступен | Назначение, сроки, достаточное количество одобренных вопросов, миграция 0035 |
| Не виден документ | Принадлежность и права приватного Storage |
| Прогресс неполный | Сохранение на сервере, миграция 0063 для видео пока отдельный PR #180 |

## Что ещё разрабатывается

- **Директор и закреплённые администраторы:** видимость только своих учеников, задачи/чаты ответственному и безопасная передача при переназначении — план PR #200.
- **Скоринг здоровья** по оплате, теории, вождению и документам — план.
- **Уведомление о трёх и более свободных слотах**, не чаще одного раза в час — план.
- **Push до подтверждения почты** — спецификация PR #198, не готовая функция.

Инструкция описывает пользовательские действия, а не серверные команды. Перед обучением персонала проверить её шаги на тестовой PWA с тремя ролями. Рабочие данные учеников и production-настройки для учебных упражнений не использовать.
