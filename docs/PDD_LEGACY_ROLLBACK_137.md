# Старый курс ПДД: проверка и возврат (PR #137)

Проверка SQL Editor 2026-10-14 подтвердила: `SELECT count(*), count(content) FROM public.pdd_articles` вернул `0, 0`. Поэтому миграция `0050_backup_legacy_pdd_articles.sql` завершилась исключением, транзакция откатилась; **не применять её повторно**, пока таблица пуста. Старый учебный каталог не хранится в этой таблице.

## Что составляет прежний курс

- `src/pages/pddTopics.ts`: статический перечень 38 разделов с ID `1`–`38`.
- `src/pages/StudentTheorySectionPage.tsx`: `StudentTheoryCoursePage`, список ПДД и `StudentPddTopicPage`. Подробные блоки читаются из `public.pdd_articles`; при отсутствии статьи показывается «Материал раздела будет добавлен из файла».
- `src/App.tsx`: маршруты старого курса.
- Отметки «прочитано» сохраняются в `localStorage` по ключу `read-pdd-topics`, а не в `pdd_articles`.

## Безопасный порядок включения нового курса

1. Перед изменениями записать commit SHA текущего рабочего `main` и убедиться, что `src/pages/pddTopics.ts`, `src/pages/StudentTheorySectionPage.tsx` и `src/App.tsx` находятся под версионным контролем GitHub.
2. Не изменять и не удалять старые файлы. Новый студенческий просмотр создавать отдельными компонентами, с отдельным переключателем по умолчанию `off`.
3. Подготовить и проверить сценарий отката **переключателя**, не переписывая существующие 38 тем и не возвращая старые данные из пустой таблицы.
4. Перед реальным включением дополнительно получить штатный backup базы Supabase, проверить права доступа курсантов к опубликованным новым версиям и медиа, а также тесты и ссылки.
5. Отметки чтения старых тем не переносить на новые ID автоматически.

## Важно

Git защищает исходные файлы приложения, **но не** содержимое Supabase. Если в `public.pdd_articles` появятся записи до окончательного переключения, пересмотреть план SQL-бэкапа и сохранить их отдельно. Никакого удаления таблицы не предусмотрено.

Текущий PR только документирует подтверждённое состояние и безопасный порядок. Он не включает новый курс ученикам.
