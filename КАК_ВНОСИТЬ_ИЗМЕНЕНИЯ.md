# Как вносить изменения в проект

Этот файл помогает быстро погрузиться в контекст и правильно описывать задачи по доработке PWA для автошколы.

## Общие правила

- Проект использует **React 19 + TypeScript + Vite + Tailwind CSS v4**.
- Состояние и серверные данные управляются через **TanStack Query (React Query)**.
- Маршрутизация — **React Router v7**.
- Аутентификация и база данных — **Supabase**.
- Push-уведомления — **OneSignal**.
- Локальный запуск — через `npm run dev`.
- Перед коммитом нужно прогнать `npm run build` и `npm run lint`.

## Структура проекта

```
src/
  components/           # Переиспользуемые UI-компоненты
    ui/                 # Button, Input, Card, Badge
    Layout.tsx          # Шапка, боковое меню, выход
    NotificationButton.tsx
  features/             # Фиче-модули
    auth/               # Контекст авторизации
    schedule/           # Расписание и занятия
    instructors/        # Работа инструктора со учениками
    admin/              # Административные функции
  hooks/                # Общие React-хуки (например, useAuth)
  lib/                  # Инициализация внешних сервисов
    supabase.ts
    onesignal.ts
  pages/                # Страницы приложения
  routes/               # Защищённые маршруты
  types/                # TypeScript-типы
  utils/                # Утилиты (cn — clsx + tailwind-merge)
supabase/
  migrations/           # SQL-миграции
```

## Как правильно описать задачу

Чем конкретнее описание, тем точнее будет результат. Используй шаблон:

1. **Какой кабинет / роль** — ученик, инструктор, админ.
2. **Какая страница / раздел** — расписание, профиль, список учеников и т.д.
3. **Что нужно добавить или изменить** — кнопка, фильтр, таблица, поле, карточка.
4. **Где брать данные** — существующая таблица, новая таблица, вычисление на клиенте.
5. **Кому доступно** — только админ, инструктор, все роли.

### Примеры хороших запросов

- «В кабинете инструктора на странице "Мои ученики" добавь поле "Комментарий" для каждого ученика. Комментарий должен сохраняться в Supabase и отображаться в карточке.»
- «В админке добавь страницу "Группы" с возможностью создавать, редактировать и удалять группы.»
- «В кабинете ученика на странице расписания добавь фильтр по типу занятия: теория / практика / все.»

### Примеры плохих запросов

- «Сделай лучше» — непонятно, что именно.
- «Добавь CRM» — слишком большой объём, нужно разбить на этапы.
- «Пофикси баг» — без указания, где и как воспроизвести.

## Порядок работы над изменениями

### Мелкие правки (одна страница, один компонент)

1. Пользователь описывает задачу.
2. Я нахожу нужные файлы и вношу изменения.
3. Проверяю сборку (`npm run build`) и линтер (`npm run lint`).
4. Показываю, что изменилось.

### Средние правки (новая страница, новая таблица)

1. Пользователь описывает задачу.
2. Я уточняю детали, если нужно.
3. Создаю или обновляю SQL-миграцию в `supabase/migrations/`.
4. Добавляю типы в `src/types/index.ts`.
5. Создаю hook для работы с данными в `src/features/<module>/`.
6. Создаю или обновляю страницу в `src/pages/`.
7. Добавляю маршрут в `src/App.tsx`.
8. Проверяю сборку и линтер.

### Крупные изменения (новый кабинет, CRM, родительский доступ)

1. Перед кодом входим в режим планирования.
2. Согласовываем архитектуру и этапы.
3. Выполняем по очереди.
4. После каждого этапа проверяем сборку.

## Чек-лист перед завершением задачи

- [ ] Код не ломает существующий функционал.
- [ ] `npm run build` проходит без ошибок.
- [ ] `npm run lint` не выдаёт предупреждений.
- [ ] SQL-миграция обновлена, если менялась схема.
- [ ] Новые env-переменные добавлены в `.env.example`.
- [ ] README или этот файл обновлены, если изменения касаются запуска или архитектуры.

## Полезные команды

```bash
npm run dev          # локальный запуск
npm run build        # production-сборка
npm run lint         # проверка линтером
npm run preview      # просмотр production-сборки
```

## Контакты и доступы

- Supabase: локальный через Docker или облачный проект.
- OneSignal: нужен App ID для push-уведомлений.
- Vercel: для production-деплоя.
