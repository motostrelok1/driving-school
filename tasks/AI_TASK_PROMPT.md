# Базовый промпт для ИИ-задач

Ты работаешь над проектом driving-school-pwa. Это React + TypeScript + Vite + Tailwind CSS v4 PWA для автошколы с Supabase, TanStack Query, React Router и OneSignal.

Работай только в рамках текущей задачи. Не пытайся улучшать весь проект сразу.

## Что прочитать перед началом

Перед любой задачей обязательно прочитай:

1. AI_TASK_PROMPT.md
2. TASK_TEMPLATE.md
3. конкретный task-файл, который дал пользователь
4. docs/project-map.md
5. docs/mvp-scope.md
6. status/modules.md

Дополнительно прочитай только файлы, перечисленные в разделе "Контекст" конкретной задачи.

Не читай весь проект без необходимости. Соседние файлы можно открыть только если они прямо нужны для понимания импорта, типа или поведения.

## Правила работы

1. Выполняй только цель текущей задачи.
2. Разделяй UI, логику, данные, интеграцию и тесты.
3. Если задача про UI, не меняй бизнес-логику без явной необходимости.
4. Если задача про логику, не переделывай внешний вид без явной необходимости.
5. Не трогай файлы вне раздела "Можно менять", кроме случаев, когда без этого задача невозможна. Если нужно выйти за границы, сначала объясни причину.
6. Не меняй схему Supabase без отдельной data-задачи.
7. Не добавляй новые зависимости без согласования.
8. Следуй текущим паттернам проекта: pages собирают экран, features содержат доменную логику, components содержат переиспользуемый UI, lib содержит внешние сервисы.
9. Для серверных данных используй TanStack Query hooks.
10. Для Supabase-операций учитывай роли и RLS.

## Куда писать результат

После выполнения задачи обязательно обнови:

1. Сам task-файл: статус, готовность, результат, что проверено, что осталось.
2. Отдельный отчет в tasks/reports/<тип>/<название-задачи>.md.
3. status/modules.md, если изменилась оценка готовности модуля.
4. tasks/backlog.md, если появились новые задачи.
5. planning-dashboard.html через команду `npm run dashboard:update`, если менялись `status/modules.md` или `status/roadmap.md`.

Пример отчета:

```text
tasks/reports/audit/auth.md
tasks/reports/ui/student-schedule-screen.md
tasks/reports/logic/lesson-status-update.md
```

## Формат отчета

Каждый отчет должен содержать:

```text
# Название задачи

Статус: done / partial / blocked
Дата: YYYY-MM-DD
Тип: audit / ui / logic / data / integration / test
Модуль:

## Что сделано

## Что проверено

## Измененные файлы

## Найденные проблемы

## Риски

## Следующие задачи
```

Если задача является аудитом, код не меняй. Верни список фактов, проблем, рисков и предлагаемых следующих задач.
